# Project Plan: Act Agent Worker

## Overview

Create an ActAgentWorker inspired by Cline's "Act Mode" that executes structured plans generated by the PlanAgentWorker. The worker processes plans step-by-step, executing actions (file modifications, tool calls, tests), evaluating completion, and tracking changes. Unlike Cline's synchronous approval model, this worker operates autonomously but creates detailed execution logs and checkpoints for review.

## Goals

- Execute ExecutionPlan objects step-by-step
- Use LLM to determine actions needed for each step
- Execute tools (WriteFileTool, BashTool, etc.) to implement steps
- Evaluate step completion after each action sequence
- Create Git checkpoints at milestone boundaries
- Generate detailed execution logs
- Handle errors gracefully with recovery attempts
- Follow our OOP patterns and state machine architecture

## Milestone 5 - Worker Execution Loop

Integrate all components to create the complete execution pipeline.

### 5.1 - Implement Milestone Iteration

**Intent**: Implement the core loop that iterates through milestones in the execution plan.

**Details**:
- In ActAgentWorker.execute method:
  - Iterate through execution_plan.milestones
  - For each milestone:
    1. Record decision: "Starting milestone: {title}"
    2. Create checkpoint before starting
    3. Execute all steps in milestone (call execute_step for each)
    4. Create checkpoint after completing milestone
    5. Record milestone completion to memory
  - Track current_milestone_index
  - Handle milestone failure: record error, decide whether to continue or stop
  - Create ChangeSet for each milestone

**Tests**:
- Test milestone iteration completes all milestones
- Test checkpoint creation at milestone boundaries
- Test milestone failure handling

---

### 5.2 - Implement Step Execution Loop

**Intent**: Implement the logic for executing a single step, including retry logic and evaluation.

**Details**:
- Create execute_step method in ActAgentWorker:
  1. Record decision: "Executing step: {title}"
  2. Run StepExecutionWorkflow to generate actions and execute tools
  3. Store step_result
  4. Run StepEvaluationWorkflow to check completion
  5. If evaluation failed and retries < max_retries:
     - Run ErrorRecoveryPrompt for diagnosis
     - Retry execution with recovery actions
  6. If evaluation passed, mark step complete
  7. If evaluation failed after retries, mark step failed, ask to continue or abort
  8. Record step completion to memory
- Track retry count per step (max 3)
- Update PlanStep status (mark_complete or mark_skipped)

**Tests**:
- Test step execution with successful evaluation
- Test step retry logic on failure
- Test max retries enforcement
- Test step status updates
- Test error recovery flow
- Test abort vs continue decision

---

### 5.3 - Build Complete Execute Method

**Intent**: Wire up the complete execution pipeline from plan loading to output generation.

**Details**:
- In execute method:
  1. trigger(:start), initialize_worker, load execution_plan
  2. trigger(:initialized), create initial checkpoint
  3. For each milestone: execute_milestone (which executes each step)
  4. trigger(:executed), run evaluation of full execution
  5. Run ExecutionOutputService to write logs
  6. Build ExecutionRecord result object
  7. trigger(:finish), return result
- Handle errors at each level: step errors, milestone errors, workflow errors
- Mark_failed on unrecoverable errors
- Record all decisions and transitions to memory

**Tests**:
